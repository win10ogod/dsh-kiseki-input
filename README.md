# dsh-kiseki-input

DSH desktop-operation tools backed by the existing Kiseki Input executable. Models call structured DSH tools; the plugin launches the bundled native CLI with argument arrays, returns complete command output, and converts screenshots into durable DSH image attachments. No MCP or shell command interpolation is used.

## Included runtime

Source: [win10ogod/kiseki-input](https://github.com/win10ogod/kiseki-input), commit `8fc5ae63f5c077fd607d1e5d52f650d6b64ddb67`.
Binaries: [Actions run 36242815724](https://github.com/win10ogod/kiseki-input/actions/runs/36242815724).

All five portable packages are included: Windows x64, macOS x64/arm64 and Linux x64/arm64. Windows DLL dependencies remain next to the executable. Archive checksums and origins are recorded in `runtime/manifest.json`. The optional CUA Driver is managed by upstream Kiseki on demand, not bundled here. Runtime dependencies and GUI permissions remain platform-specific.

Version 0.2.0 overlays the Windows executable with the locally built/tested CUA update. Its source patch and executable provenance are included in runtime/manifest.json and runtime/kiseki-cua-update.patch. The other four platform binaries remain from the original Actions run; the new kiseki_cua tool works through their existing full-JSON call path, while new native CLI aliases require rebuilding Kiseki on those platforms. Native macOS/Linux GUI behavior has not been tested in this integration.

The upstream workflow already publishes releases for version-tag pushes. This particular master-branch run produced Actions artifacts, so this plugin packages those directly. Installing the plugin requires neither GitHub authentication nor a C++ compiler.

## Install

```sh
dsh plugin --profile pack-test add /absolute/path/to/dsh-kiseki-input --ignore-workspace-root-check
```

The bundle registers eight tools: `kiseki_status`, `kiseki_observe`, `kiseki_capture`, `kiseki_input`, `kiseki_run`, `kiseki_job`, `kiseki_image`, `kiseki_cua`. It includes the DSH operation skill and both upstream Kiseki skills. Load `dsh-kiseki-input` for examples.

Config fields:

- `executablePath`: optional explicit native executable. Otherwise selects the bundled build for the host OS/architecture. An invalid explicit path fails; it never silently falls back.
- `cuaDriverPath` / `cuaSocket`: optional explicit CUA executable and daemon endpoint for a managed host or independent test service.
- `artifactDirectory`: optional capture/input artifact root. Defaults to the host temp directory's `dsh-kiseki-input` folder, with separate session and call directories. Image attachments are persisted by DSH.
- `cancelGraceMs`: 5000 ms grace after requested cancellation before force-killing a remaining process. This is not a normal execution timeout. On Windows Node process termination is forced and cannot guarantee release of held inputs.

Foreground commands follow DSH cancellation. Long-running commands can use `background:true` and session-owned jobs; `wait` follows cancellation and `status` is non-blocking. There is no plugin-added normal timeout, output truncation or image resizing. The plugin does not rewrite conversation messages or trigger agent continuation.

Targets and modes are explicit. It preserves upstream coordinates, precision/timing arguments, snapshot tokens and backend errors. CUA's default session name is derived from the DSH session; raw provider JSON needs the same explicit session name when required. Jobs do not isolate the physical desktop: concurrent agents must coordinate shared targets. Detached upstream daemons/recorders use their upstream stop commands, separate from the tracked CLI job.

## Refresh from Actions

```sh
gh run download 36242815724 -R win10ogod/kiseki-input -D artifacts/upstream
python3 scripts/prepare-runtime.py --artifacts artifacts/upstream --source ../kiseki-input --run 36242815724
python3 scripts/overlay-runtime.py --source ../kiseki-input --executable ../kiseki-input/build/Release/kiseki.exe --platform win32-x64
npm ci
npm run check
npm pack
```

Use a source checkout matching the chosen run's head SHA. The preparation script verifies SHA-256 sidecars, preserves native runtime files, and bundles upstream skills/docs. Future runtime changes can be packaged without rewriting the DSH tool bridge.

## Validation

`npm run check` exercises argument fidelity, errors, jobs/cancellation, session separation, capture conversion, and plugin wiring. Windows integration evidence is generated by `node scripts/live-test.mjs` with the dedicated test window created by `scripts/test-window.ps1`. Read `artifacts/live-test/latest.json` and its referenced `report.json` for observed results; do not infer macOS or native Linux GUI validation from Windows/WSL tests.

DSH interface inspected against `0.1.7-rc.2` and tested with `0.2.1-alpha.1` and `0.2.2-rc.1`; Kiseki packaged version `0.1.0` from the commit above.

## Current CUA support

`kiseki_cua` sends complete provider JSON through Kiseki, including semantic_v2 browser snapshots, continuation/scope refs, capture-bound actions, sessions, cursor themes and visual-region requests. `useSession:true` supplies the DSH session label while retaining an explicitly supplied session. Provider refusals remain failures even if an older Kiseki executable returns exit code zero. `submitted`/`unverifiable` results remain visible and require observation. Perception availability depends on its separately installed preview extension.
